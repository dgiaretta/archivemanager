JVM configuration

The JVM's default charset is not UTF-8. This is the single most likely cause of Dhivehi text corrupting somewhere in this app's own pipeline (as opposed to already being corrupted in your source file) — Java 17 predates Java 18's "UTF-8 by default" change, so on Windows specifically, an unconfigured JVM falls back to the Windows ANSI code page, which has no Thaana support at all. Fix: launch with -Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8 explicitly — see run.bat in this project, or the README's internationalisation section.

If LANG/LC_ALL/LC_CTYPE are all "(not set)", or something like plain C or POSIX (ASCII-only, no Unicode support), that's a locale configuration issue independent of which OS this is running on — it affects Linux/WSL exactly as much as Windows. C.UTF-8 specifically is not one of those cases — it's C-style collation with full UTF-8 character support, a real and correctly Unicode-capable locale often used deliberately in containers and minimal server images. run.sh (Linux/macOS) and run.bat (Windows) force UTF-8 explicitly at the JVM level regardless of the surrounding locale, for the (Java 17 and earlier, pre-JEP-400) cases where it matters; on Java 18+ the JVM already defaults to UTF-8 everywhere, so this class of fix has nothing left to do.

Still seeing question marks with a real upload?

The test string above only exercises the rendering half of the pipeline — it never went through file reading at all. If your source file passes this page but still shows question marks after importing it, or if you want to test the exact file that's giving you trouble directly, use the XLSX read test: upload the actual file and see precisely what Apache POI extracts from it, before anything else in this app gets involved.

If that page also renders correctly but a real import still corrupts, the one remaining untested link is Jena/TDB2's own storage round trip — neither this page nor the XLSX read test actually writes to or reads from the data graph at all. The TDB2 round-trip test writes the same Dhivehi string into the data graph, commits, and reads it back in a genuinely separate request — the same round trip a real import and a later Catalogue page view go through.
