Bulk upload

Upload a Bulk Upload Spreadsheet (the 26-column format from NAM's Preservation Policy and Implementation Plan, "Upload Spreadsheet and Accession Register") as either .xlsx or .csv. Column headers must match the spreadsheet's field names (matching is case- and space-insensitive, so FixityHashSHA256 and fixity hash sha256 are treated the same; Original Title is also accepted as an alternate header for Title). Repeatable fields (Subject, Description, Contributor, Date, Type, Format, Identifier, Source, Language, Relation, Coverage, Rights, Provenance, FormatInfo, Semantics, OtherRI) accept multiple values in one cell separated by ;.

Prefer .xlsx over .csv if any of your data is in Dhivehi (or any non-Latin script). Excel's plain "CSV (Comma delimited)" export writes the file using the system's ANSI code page, not UTF-8, unless "CSV UTF-8 (Comma delimited)" is chosen specifically -- and the Windows ANSI code page has no representation for Thaana script at all, so that export step silently replaces every Dhivehi character with a literal ? in the file itself, before this app ever sees it. That corruption is permanent once it's in the CSV; uploading an already-corrupted CSV again won't recover it, however this app handles encoding. Uploading the original .xlsx avoids the lossy step entirely.

Each row becomes one Catalogue record. The whole upload becomes one Accession Register entry linking every record it created. No column is required -- a blank cell just means that property isn't recorded for this row, which is normal; rows are only skipped (and reported, not silently dropped) if something genuinely unexpected goes wrong reading them.
