Transform Data Object

A Transformation rewrites this Data Object in another format — here, by mapping it to a format described in the archive, or with another application. Here, it is decoded with its own Representation Information, each element of the new format is made from its elements as you say below, and the result is written with the new format's DFDL description. The new data is then decoded again with that description to check each Transformation Information Property. Doing it keeps the new data in the archive and records a new Data Object, in an AIP Version whose Provenance Information records the Transformation — this Data Object is left as it is.

The new format

No format can be transformed into yet: one needs a DFDL description in the archive, used by some Data Object. Describe it in RepInfo Tools and save it to the archive.

What makes each element of the new format

An element that repeats occurs once for each occurrence of the element of the old format it repeats over; inside it, the old format's elements under that one are that occurrence's. A value is copied (times a scale, plus an offset, if given), counted, or a constant. Elements were first matched by name or meaning: check them.

Transformation Information Properties to check

The values that must survive the Transformation. Each is checked by decoding the new data with its own description and comparing physical values (after each side's scale and offset) — within the tolerance given, in the values' units, or else what the types carry. Those this Data Object's Information Object already has are marked; the others are added to it when you transform.

Or transform it with another application

If another application does the Transformation — a format converter, a script, a mission's own software — download the data and its description, transform it there, then upload the result here and say what was done. That record becomes the new AIP Version's Provenance Information, so whoever reads it later knows how the data came to be.
