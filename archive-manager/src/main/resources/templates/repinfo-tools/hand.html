Format: DFDL by hand

Write Python code for the generated drb-python driver to call, for what the element tree can't express. The driver still reads the element tree; the add-in plugs in around it, through any of these functions:

  • prepare(data) — gets the file's bytes before they're read, and returns the bytes to read: decrypt or decompress them here.
  • check(root) — after decoding: returns a list of problems (checksums, CRCs, cross-checks), added to what the checks add-on reports.
  • metadata(root) — returns a dict merged into what the metadata add-on returns.
  • restore(data) — when the file is written back: undoes prepare() (e.g. encrypts again), returning the bytes to write.

root.original_bytes are the file's bytes, root.decoded_bytes what prepare() returned, and root's children the decoded elements. The add-in is addin.py in the downloaded package, and is saved to the archive with the driver.

An add-in is Python code, which runs with the full rights of whoever uses the driver. It's checked to be valid Python, but it can't be checked to be safe. This server runs add-ins in sample tests. This server doesn't run add-ins in sample tests (archive.drb-python.run-hand-written-add-ins), so test the downloaded package elsewhere.

Write the DFDL description yourself, for what the editor's element tree can't express — checksums, encryption, other compression, records spread over several lines, and anything else the language can do. Once saved, it replaces the generated description in the preview, the sample test, the download and when saving to the archive. The element tree still provides the meanings (semantic names, units, codes) saved as Semantic Representation Information, but a sample test of a hand-written description shows the engine's own tree rather than lining it up with the element tree.

A sample test runs the description inside this application, so it's checked first: no DOCTYPE or files included from elsewhere (DFDL may include Daffodil's own built-in schemas); for Kaitai Struct, no imports or custom process: routines (zlib, xor, rol and ror are built in); for DRB, no queries calling Java or reading files.

The element tree has changed since this was written, so what it generates now is different. Check whether the hand-written description needs the same change.
