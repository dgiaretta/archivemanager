Or describe a FITS file from its headers

A FITS file describes itself: its headers say what each HDU holds. Its headers become a description of that file in particular — each header a record of its keyword records, each pointing to the keyword's meaning in the FITS keyword dictionary (FITS Standard 4.0); each image as rows of pixels, typed by BITPIX, with BUNIT, BSCALE, BZERO and BLANK as their units, scale, offset and fill value; each table's columns typed by TFORMn and named by TTYPEn, with TUNITn, TSCALn, TZEROn, TNULLn, TLMINn and TLMAXn. Then the archive can decode it, show its table and image, and say what its columns mean. Only the headers are read. A Data Object whose Representation Information says it's FITS can be described the same way from its page.

Or read a description in EAST

A Data Description Record in the CCSDS data description language EAST (CCSDS 644.0-B-3): its logical package and its physical package. It's kept as written, and tested with the EAST interpreter. Its records, arrays, enumerations and variants also become the element tree, with each enumeration's literals as the meanings of its codes, so Kaitai Struct, DFDL and DRB descriptions can be generated from it and tested against sample data too - when the tree can express it; if not, it's kept as EAST only.

Or describe data whose format is already known

For a spreadsheet or delimited text, whose structure is defined by a published specification and which software already reads: describe only what each column means. It's saved as Semantic Representation Information, used together with a format profile (Structure Representation Information) and the software that reads the format (Other Representation Information: any one of several applications), or with Representation Information already in the archive.
